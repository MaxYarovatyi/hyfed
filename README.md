# HyFDCA — Hybrid Federated Dual Coordinate Ascent

Research implementation of a federated learning system for **personalised monitoring of psycho-emotional state from biometric data**. Each client (patient device) trains on its own data; only noised model updates leave the device.

## Idea
The model is split into two parts:
- a **global** part shared by all clients and aggregated by a coordinator (FedAvg),
- a **local** part that stays on the device and personalises predictions for one patient.

Local training uses SDCA (stochastic dual coordinate ascent). Updates sent to the coordinator are protected with **differential privacy** (Gaussian mechanism with update clipping and an (ε, δ) budget).

## Solution structure
| Project | Role |
|---|---|
| `Core` | Algorithms (`LocalSdcaSolver`, `GlobalAggregator`, `GaussianMechanism`), data loading, feature engineering (`ImpactMatrix`, `LocalRegressorPipeline`), models |
| `Communication` | gRPC contract (`Protos/fl_service.proto`): pull global model, submit update, stream round broadcasts |
| `Coordinator` | ASP.NET Core gRPC server: collects client updates, aggregates, tracks convergence |
| `Client` | Simulator that runs several virtual clients against the coordinator |
| `Evaluation` | In-process FL runner and ablation study; writes CSV results |
| `Tests` | Smoke tests for the local solver |

## One federated round
1. Client calls `GetGlobalModel` and receives the current global weights
2. Client trains locally with SDCA on its own samples
3. Client clips and noises its update, then calls `SubmitUpdate`
4. When enough clients have submitted, the coordinator aggregates and starts the next round (pushed to subscribers via `SubscribeToRounds`)

## Running
Requires the .NET 10 SDK.
```
dotnet run --project Coordinator     # gRPC on http://localhost:5050 (HTTP/2)
dotnet run --project Client          # in a second terminal: 5 virtual clients
dotnet run --project Tests           # solver smoke test
dotnet run --project Evaluation      # ablation study → CSV files in Evaluation/
```
`Evaluation/Program.cs` currently reads the patient data set and feature config from absolute local paths; change them to your own before running. The patient data is synthetic and generated by a separate tool (not included).

## Results
The ablation study compares global-only federated training, local-only training, full HyFDCA and HyFDCA without the impact matrix. Metrics (R², MAE, MSE on train and test) are in `Evaluation/ablation_results.csv`, per-patient results and convergence curves in the other CSV files.

## Tech stack
C#, .NET 10, ASP.NET Core, gRPC / Protocol Buffers, MathNet.Numerics.
